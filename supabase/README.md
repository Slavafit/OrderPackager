# Настройка Supabase

Для новой базы сначала выполните `setup.sql`. Затем создайте пользователя в
**Authentication → Users** и выполните `migrate_to_auth.sql`, указав в нём UID этого
пользователя.

Для синхронизации справочника клиентов после основной настройки один раз выполните
`add_clients_sync.sql` в **SQL Editor**. При первой успешной синхронизации существующие
клиенты с устройства будут загружены в облако. Если облачный список уже есть,
уникальные локальные клиенты добавятся без дублирования.

Для синхронизации циклического списка затем один раз выполните
`add_cyclic_items_sync.sql`. Порядок позиций сохраняется; на свежей установке
облачный список заменяет встроенные демонстрационные записи.

Приложение показывает экран входа и использует Supabase Auth. Пароль не сохраняется:
локально хранится только обновляемая сессия. Таблица заказов защищена RLS и каждый
пользователь видит только строки со своим `owner_id`.

## Справочник товаров (v1.25)

Перед загрузкой новой версии в Google Play выполните
[`add_product_catalog.sql`](add_product_catalog.sql) в **Supabase → SQL Editor**.
Скрипт создаёт общий каталог, таблицу товаров пользователей и два RPC. Он не
удаляет заказы или справочники. Повторный запуск не перезаписывает каталог.

Общий каталог находится в `public.order_packer_catalog`, строка `id = 1`,
поле `payload` (JSON с categories/products). Меняйте его через SQL Editor / Table
Editor с административными правами: после синхронизации изменения появляются
на устройствах без выпуска новой версии. Сохраняйте schemaVersion = 1,
существующие ID и структуру полей; не удаляйте используемые категории. Приложение
не даёт обычным пользователям изменять общий справочник.

Собственные товары хранятся в `public.order_packer_custom_products`. Они доступны
только владельцу `auth.uid()`. Пользователи разных аккаунтов не видят товары
друг друга. Вход одним аккаунтом на двух устройствах даёт общий личный каталог.
Добавление выполняется через RPC, без возможности подменить owner_id или
перезаписать общий товар. В этой версии реализовано создание, без удаления и
редактирования уже созданных товаров.

Room хранит общий кэш и пользовательские товары с ownerId. Новые товары сначала
сохраняются на устройстве с флагом pending. Отправка идемпотентна по UUID; при сбое
данные остаются локально. Синхронизация запускается после создания товара, при
открытии состава, при входе и восстановлении сети. Активному офлайн-пользователю
не требуется обновление сессии для локального добавления. Впервые войти в аккаунт
по-прежнему нужно с интернетом.

После SQL-миграции: создайте товар на устройстве A, синхронизируйте и откройте
состав на B под тем же аккаунтом. Проверьте добавление без сети и последующую
отправку, а также отсутствие чужих товаров под другим аккаунтом.
